JavaScript 기본 개념 정리

핵심 개념 + 우리 할 일 목록(todo) 프로젝트에 적용하는 방법

변수자료형함수배열 메서드 객체·구조 분해DOM·이벤트비동기 모듈저장소적용 제안

1. 변수와 스코프

const a = 1;      // 재할당 불가 (기본으로 사용)
let b = 2;        // 재할당 가능
// var            // 함수 스코프, 호이스팅 문제 → 쓰지 않기

const/let은 블록 { } 안에서만 유효합니다. const도 객체·배열의 내부 값은 바꿀 수 있고, 변수 자체의 재할당만 막습니다.

프로젝트: DOM 요소 참조는 const, 바뀌는 상태인 todos만 let을 쓰고 있어 이미 올바른 사용입니다.

2. 자료형과 비교

원시형: string number boolean null undefined symbol bigint, 그 외는 객체(배열·함수 포함).

0 == '0'    // true  (형변환)
0 === '0'   // false (항상 === 사용)
// falsy: false, 0, '', null, undefined, NaN
const text = input.value.trim();
if (!text) return;   // 빈 문자열은 falsy
프로젝트: 입력값 검증에 falsy 개념을 이미 쓰고 있습니다 (if (!text) return;).

3. 함수와 화살표 함수

function add(a, b) { return a + b; }
const add2 = (a, b) => a + b;          // 화살표 함수
const greet = (name = '손님') => `안녕, ${name}`;  // 기본값, 템플릿 리터럴

함수는 값이므로 인자로 전달할 수 있고(콜백), 바깥 변수를 기억합니다(클로저).

프로젝트: () => toggleTodo(todo.id)는 클로저로 각 항목의 id를 기억하는 콜백입니다.

4. 배열 메서드

메서드역할원본 변경
map각 요소를 변환한 새 배열X
filter조건에 맞는 요소만 새 배열X
find첫 번째 일치 요소X
some / every하나라도 / 모두 만족?X
reduce하나의 값으로 누적X
push / splice추가 / 삭제O
프로젝트: filter(t => !t.done).length로 남은 개수를, map으로 완료 토글을, filter로 삭제를 구현했습니다.

5. 객체, 스프레드, 구조 분해

const todo = { id: 1, text: '공부', done: false };
const next = { ...todo, done: true };      // 복사 후 일부만 변경
const { text, done } = todo;               // 구조 분해
const copy = [...todos, newTodo];          // 배열 스프레드

상태를 직접 수정하지 않고 새 값을 만드는 방식(불변 업데이트)은 버그를 줄여 줍니다.

프로젝트: { ...t, done: !t.done }이 바로 불변 업데이트입니다.

6. DOM과 이벤트

const el = document.querySelector('#todo-list');
const li = document.createElement('li');
li.textContent = '안전한 텍스트 삽입';   // innerHTML보다 XSS에 안전
el.append(li);
form.addEventListener('submit', (e) => { e.preventDefault(); });

이벤트 위임

항목마다 리스너를 달지 않고 부모에 하나만 달아 e.target으로 구분합니다.

list.addEventListener('click', (e) => {
  const id = Number(e.target.closest('li')?.dataset.id);
  if (e.target.matches('.delete')) deleteTodo(id);
});
프로젝트: 사용자 텍스트는 textContent로 넣고 있어 안전합니다. 다만 render()마다 리스너를 새로 다는 구조라 이벤트 위임으로 줄일 수 있습니다.

7. 비동기: Promise, async/await

async function load() {
  try {
    const res = await fetch('/api/todos');
    if (!res.ok) throw new Error(res.status);
    return await res.json();
  } catch (err) {
    console.error(err);
    return [];
  }
}

이벤트 루프 덕분에 await 중에도 화면은 멈추지 않습니다. setTimeout, fetch가 대표적인 비동기 API입니다.

프로젝트: 지금은 localStorage(동기)만 써서 비동기가 필요 없습니다. 서버 연동 시 save()/load()를 async로 바꾸면 됩니다.

8. 모듈 (ES Modules)

// store.js
export function loadTodos() { /* ... */ }
// app.js
import { loadTodos } from './store.js';
// index.html: <script type="module" src="app.js"></script>

주의: 모듈은 file://로 열면 CORS로 막히므로 python3 -m http.server 같은 로컬 서버가 필요합니다.

9. 저장소와 JSON

localStorage.setItem('todos', JSON.stringify(todos));
const todos = JSON.parse(localStorage.getItem('todos') || '[]');

저장 데이터가 깨졌을 때 JSON.parse는 예외를 던지므로 try/catch로 감쌉니다.

10. 우리 프로젝트에 적용하면 좋은 것 (우선순위순)

  1. JSON.parse 방어 — 저장값이 손상되면 앱 전체가 안 뜹니다. try/catch로 감싸 빈 배열로 폴백합니다. 
    function load() {
  try { return JSON.parse(localStorage.getItem('todos')) ?? []; }
  catch { return []; }
}
  2. id 생성 개선 — Date.now()는 같은 밀리초에 두 번 추가하면 충돌할 수 있습니다. crypto.randomUUID()를 쓰면 안전합니다.
  3. 이벤트 위임 — render()의 리스너 생성을 list 하나로 모읍니다 (data-id 사용).
  4. 필터 기능 추가 — 전체/진행 중/완료 탭. filter 상태 하나를 두고 render()에서 todos.filter(...)만 바꾸면 됩니다.
  5. 수정 기능 — 더블클릭 시 span을 input으로 교체하고 map으로 텍스트를 갱신합니다.
  6. 상태/뷰 분리 — store.js(저장·상태), app.js(렌더·이벤트)로 모듈 분리. 로컬 서버 필요.
  7. 접근성 — 체크박스에 aria-label, 카운트에 aria-live="polite"를 달면 스크린리더가 변경을 읽어 줍니다.
추천: 1번과 2번은 몇 줄이면 끝나는 안정성 개선이니 먼저 하고, 기능을 늘리고 싶다면 4번(필터)이 가장 자연스럽습니다.
